# Публикация GreenTaxi: Vercel + Neon

Целевая схема: Vercel размещает интерфейс и Node.js API, Neon PostgreSQL хранит заказы, сотрудников, сессии, профили пассажиров и телефонные обращения. Локальный `.data/greentaxi.sqlite` не подходит для Vercel: файловая система serverless-функции не обеспечивает постоянное хранение базы.

Эта инструкция описывает подготовленные исходники и действия для публикации. Создание проектов и работа настоящего production-домена должны быть проверены отдельно; наличие конфигурации в Git не означает, что сайт уже опубликован.

## 1. Подключить полный репозиторий

В ветке `main` репозитория `edgarcho333/greentaxi` должны находиться полные исходники приложения. Самостоятельный `GreenTaxi.html` и ZIP-превью показывают дизайн, но не заменяют сервер и базу.

Импортируйте и разворачивайте именно **`main`**. Если веткой по умолчанию GitHub остаётся `preview-download-2026-10-07`, выберите `main` в настройках Default branch GitHub до импорта либо явно задайте `main` в Vercel Project Settings → Git → Production Branch. Ветка `preview-download-2026-10-07` содержит только HTML/ZIP-превью.

Корневой каталог проекта Vercel — корень репозитория. Настройки:

| Параметр | Значение |
| --- | --- |
| Framework Preset | Vite |
| Production Branch | `main` |
| Node.js | 24.x |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

`vercel.json` содержит настройки сборки и маршруты: `/api/*` обслуживает `api/index.ts`, остальные страницы — SPA из `dist`. `api/index.ts` переиспользует инициализированное Express-приложение внутри экземпляра функции. В холодных экземплярах состояние загружается из Neon, а не из памяти прежнего процесса.

## 2. Создать Neon и связать с Vercel

Добавьте официальную интеграцию Neon через Vercel Marketplace/Storage, создайте новый Neon-проект и подключите его к проекту GreenTaxi. Используйте отдельную production-базу/ветку и, по возможности, близкие регионы базы и функций. Официальная инструкция: [Neon + Vercel](https://neon.com/docs/guides/vercel-native-integration).

Привяжите **pooled** строку подключения к переменной `DATABASE_URL` в окружении **Production**. Если интеграция добавила переменную с префиксом, приложению всё равно нужна переменная с точным именем `DATABASE_URL`. Не копируйте её в исходники или переменные `VITE_*`.

Сохраните параметры TLS в выданной строке, включая `sslmode=require`. Сервер удаляет конфликтующие SSL-параметры из DSN и включает проверку сертификата PostgreSQL-драйвером. Не применять `rejectUnauthorized: false` или отключение TLS для Neon. `sslmode=disable` допускается кодом только для отдельной локальной PostgreSQL-проверки.

Preview-развёртывания не должны использовать production-данные. Если нужен работающий preview API, подключите отдельную Neon-ветку к окружению Preview. Само наличие preview-страницы не подтверждает готовность production.

## 3. Подготовить базу и первого сотрудника

В Vercel Environment Variables → Production нужны:

| Имя | Назначение |
| --- | --- |
| `DATABASE_URL` | Секретная строка подключения Neon PostgreSQL |
| `ADMIN_SETUP_TOKEN` | Временный секрет только для создания первого сотрудника |

`NODE_ENV=production` используется production-рантаймом; `DB_PATH` на Vercel не задаётся. Сгенерируйте `ADMIN_SETUP_TOKEN` локально из не менее чем 32 случайных байт, например:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Сохраните значение в настройках Vercel, не в Git, клиентском коде или чате.

Перед первым запуском production выполните из полного checkout с Node.js 24:

```sh
npm ci
NODE_ENV=production npm run db:migrate
```

Для этой команды `DATABASE_URL` должен быть предоставлен локальному процессу через защищённое окружение. Не вставляйте пароль базы в командную строку или файл в репозитории. `db:migrate` выполняет серверную инициализацию схемы; повторный запуск безопасен. Сборка `npm run build` сама по себе не заменяет миграцию базы. После сборки эквивалентная команда — `NODE_ENV=production node dist-server/database.js`.

Инициализация также предусмотрена при старте API под PostgreSQL advisory lock. Начальные настройки и три демонстрационные точки добавляются только в новую базу и не перезаписывают настройки оператора.

Запустите Production deployment. Откройте `/admin`, введите секрет первичной настройки и создайте сотрудника. После этого удалите `ADMIN_SETUP_TOKEN` из Production Environment Variables и выполните новое развёртывание: изменённые переменные не применяются к уже запущенному deployment автоматически. Учётная запись сохранится в Neon.

В настройках панели замените тестовые точки Тбилиси реальными названиями/адресами и внесите точное место в Дидубе до приёма настоящих поездок.

## 4. Проверить опубликованный сайт

Откройте итоговый production-домен в приватном окне без входа в Vercel. Публичная форма и приём Android-событий не должны блокироваться Vercel Deployment Protection. Закрытые preview-домены можно оставить защищёнными; приложению Android нужен доступный production-домен. См. [Deployment Protection](https://vercel.com/docs/deployment-protection).

Проверьте одну тестовую заявку: она появляется во входящих, назначение слота подтверждает её, перезагрузка страницы сохраняет данные. Без входа `/api/admin/*` и поиск сохранённого профиля пассажира должны быть недоступны. Публичная форма не возвращает имя или прежние адреса по введённому телефону.

Для Android укажите в приложении **корень** сайта, например `https://yourdomain.ge`, без `/api` и других путей. Создайте отдельный токен устройства в панели. Проверка API синтетическим событием не подтверждает работу настоящего SIM-звонка на Redmi; процедура проверки устройства описана в [Android-интеграции](android-integration.md).

## Файлы и повторные развёртывания

За эту схему отвечают `vercel.json`, `api/index.ts`, `server/database.ts` и `server/migrations/`. Замороженная установка выполняется через `npm ci` и `package-lock.json`. При изменении схемы сначала выполняйте `npm run db:migrate` для нужной базы, затем публикуйте соответствующие исходники. Заказы остаются в Neon между развёртываниями.

В облачной среде разработки npm-кэш доступен по `/workspace/.cache/npm`: `npm ci --cache /workspace/.cache/npm`. Это настройка разработки, её не нужно переносить в команду установки Vercel.

Настройки Vercel описаны также в [официальной документации конфигурации проекта](https://vercel.com/docs/project-configuration). Фактическое размещение, доступность домена и Neon-проекта подтверждаются успешным запуском production и перечисленными проверками.
