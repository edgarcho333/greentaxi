# GreenTaxi

Сайт бронирования поездок Гори ↔ Тбилиси и административная панель. Интерфейс на грузинском языке; пассажир отправляет заявку без регистрации, сотрудник назначает слот и подтверждает заказ. В первой версии нет SMS-проверки, уведомлений пассажиров, платежей или водителей. Все сотрудники имеют одинаковые права.

Требования и defaults первой реализации: [техническое задание](docs/technical-spec.md).

Публикация сайта в интернете: [Vercel + Neon PostgreSQL](docs/deployment-vercel-neon.md). Для этого используется полный репозиторий, а не HTML-превью; наличие инструкции и конфигурации ещё не подтверждает создание проектов или доступность production-домена.

Для Vercel выберите **Production Branch `main`** с полными исходниками. `preview-download-2026-10-07` содержит только HTML/ZIP-превью; если она остаётся веткой по умолчанию GitHub, перед импортом переключите Default branch на `main` либо явно задайте ветку в Vercel.

## Открытие HTML двойным нажатием

Для просмотра дизайна без установки Node.js откройте [GreenTaxi.html](GreenTaxi.html). Этот файл содержит стили, шрифт, изображения и скрипты внутри и открывается непосредственно в браузере. Сразу отображается административная панель по исходному макету; переключение к пассажирской форме доступно через кнопку «სატესტო მონაცემები» справа внизу.

Это демонстрация с явно отмеченными тестовыми данными. Отправка настоящих заказов, изменения данных и подключение телефона доступны в серверном приложении. Исходный `index.html` запускается через сервер, как описано ниже.

Обновить самостоятельный HTML после изменений интерфейса:

```bash
npm run build:html
```

## Локальная разработка

Нужен Node.js **24.x**. Стек: React, TypeScript, Vite и Express. Локально без `DATABASE_URL` используется SQLite через встроенный модуль Node.js; отдельный сервер базы для такой разработки не нужен. Для Vercel и production используется Neon PostgreSQL.

```bash
npm ci
npm run dev
```

В этой облачной среде стандартный каталог кеша npm недоступен для записи. Для установки используйте:

```bash
npm ci --cache /workspace/.cache/npm
```

Менять `HOME` не требуется; вне облачной среды обычный `npm ci` подходит.

Сайт: `http://localhost:3000`, панель: `http://localhost:3000/admin`. По умолчанию `PORT=3000`; при необходимости его можно задать в окружении процесса.

На первом открытии `/admin` создайте сотрудника: логин, имя и пароль длиной не менее 10 символов. Дальнейший вход выполняется по логину и паролю.

Начальные три точки посадки в Тбилиси — **тестовые demo-данные**, явно помеченные в интерфейсе. Перед использованием для реальных поездок сотрудник должен вручную внести названия и адреса точек в настройках. Точный адрес высадки в Дидубе также редактируется там и будет заполнен позднее.

## Сборка и production-запуск

Перед production-запуском задайте `DATABASE_URL` для PostgreSQL через защищённое окружение. На Vercel используется Neon; подробный порядок создания проектов и переменных приведён в [инструкции публикации](docs/deployment-vercel-neon.md).

```bash
npm run build
NODE_ENV=production npm run db:migrate
npm start
```

Миграция безопасна при повторном запуске; сборка не запускает её автоматически. API также инициализирует схему при старте под блокировкой PostgreSQL. Production-сервер размещается за HTTPS-прокси: защищённые cookies панели и подключение Android требуют HTTPS. Публикация облачной среды разработки сама по себе не размещает сайт в интернете.

Перед созданием первого сотрудника задайте `ADMIN_SETUP_TOKEN` через окружение сервера: сгенерируйте его локально из не менее 32 случайных байт. Первичная настройка сотрудника на `/admin` требует этот токен. После создания сотрудника уберите переменную из production-окружения и перезапустите процесс либо выполните новое развёртывание Vercel. Это внутренний секрет запуска: не записывайте его значение в репозиторий, README, клиентский код или чат. Пароли сотрудников также не входят в конфигурационные файлы.

## Данные

Локально без `DATABASE_URL` база сохраняется в `.data/greentaxi.sqlite`; путь меняется через `DB_PATH`. Каталог `.data` исключён из Git. В production `DATABASE_URL` обязателен, данные хранятся в PostgreSQL. SQLite-файл нельзя использовать как постоянную базу Vercel. Миграции и первоначальные demo-настройки не перезаписывают существующие заказы или настройки оператора.

## Повторные пассажиры

Сотруднику доступны сохранённые имя, последний адрес в Гори и последняя действующая точка Тбилиси по нормализованному номеру телефона. Они подставляются при новом ручном заказе и в карточке звонка; сотрудник проверяет их перед сохранением. Дату, время и количество мест для новой поездки выбирают заново.

Профиль обновляется после действий сотрудника с заказом. Публичные заявки сами не меняют сохранённые данные пассажира; публичная форма и API не раскрывают профиль по номеру телефона. До появления SMS-проверки автоподстановка работает только в защищённой панели.

## Звонки с Android

Дополнительный источник входящих — новые принятые SIM-звонки на Redmi с Android 15. Пропущенные, отклонённые и исходящие звонки не создают обращения; старый журнал не импортируется.

Сотрудник подключает устройство в настройках панели и передаёт выданный токен приложению на телефоне. Значение токена показывается при создании устройства; не сохраняйте его в репозитории или примерах конфигурации. Доступ устройства можно отключить там же.

Звонок создаёт телефонное обращение без параметров поездки. Сотрудник заполняет имя, направление, адрес, 1–4 места, дату и слот, затем одним действием создаёт подтверждённый заказ. Повторная доставка события не дублирует обращение.

API и browser-проверки используют синтетические события. Получение реального SIM-звонка на физическом Redmi Android 15 ещё требует отдельной проверки на устройстве.

## Проверки

```bash
npm test
npm run test:e2e
```

Для e2e нужен Chromium, установленный для Playwright. Если браузер ещё не установлен:

```bash
npx playwright install chromium
```

`npm run build` также проверяет TypeScript. Сценарии приёмки перечислены в ТЗ; описание сценариев не является отчётом об успешном прохождении тестов.

Без PostgreSQL-переменных browser-тесты запускают отдельный сервер на порту 3100 и создают новую SQLite-базу в уникальном каталоге `/tmp` для каждого запуска. Рабочая `.data/greentaxi.sqlite` для них не используется.

Для PostgreSQL API-тестов задайте `TEST_DATABASE_URL` тестовой базы: проверки создают и удаляют изолированные схемы. Для PostgreSQL browser-тестов задайте `E2E_DATABASE_URL` **только одноразовой тестовой базы** — этот запуск не изолирует данные отдельной схемой. Команды остаются `npm test` и `npm run test:e2e`.
