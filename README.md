# GreenTaxi

Сайт бронирования поездок Гори ↔ Тбилиси и административная панель. Интерфейс на грузинском языке; пассажир отправляет заявку без регистрации, сотрудник назначает слот и подтверждает заказ. В настройках расписания есть очередь водителей для Гори → Тбилиси. SMS-проверка, уведомления пассажиров и онлайн-оплата пока не подключены. Все сотрудники имеют одинаковые права.

Требования и defaults первой реализации: [техническое задание](docs/technical-spec.md).

Публикация сайта в интернете: [Vercel + Neon PostgreSQL](docs/deployment-vercel-neon.md). Для этого используется полный репозиторий, а не HTML-превью; наличие инструкции и конфигурации ещё не подтверждает создание проектов или доступность production-домена.

Для Vercel выберите **Production Branch `main`** с полными исходниками. `preview-download-2026-10-07` содержит только HTML/ZIP-превью; если она остаётся веткой по умолчанию GitHub, перед импортом переключите Default branch на `main` либо явно задайте ветку в Vercel.

## Открытие HTML двойным нажатием

Для просмотра дизайна без установки Node.js откройте [GreenTaxi.html](GreenTaxi.html). Этот файл содержит стили, шрифт, изображения и скрипты внутри и открывается непосредственно в браузере. Сразу отображается административная панель по исходному макету; переключение к пассажирской форме доступно через кнопку «სატესტო მონაცემები» справа внизу.

Это демонстрация с явно отмеченными тестовыми данными. Отправка настоящих заказов, изменения данных и подключение телефона доступны в серверном приложении. Исходный `index.html` запускается через сервер, как описано ниже.

Обновить самостоятельный HTML после изменений интерфейса:

```bash
npm run build:html
```

## Локальная разработка

Нужен Node.js **24.x**. Стек: React, TypeScript, Vite и Express. Локально без `DATABASE_URL` используется SQLite через встроенный модуль Node.js; отдельный сервер базы для такой разработки не нужен. Для Vercel и production используется Neon PostgreSQL.

```bash
npm ci
npm run dev
```

В этой облачной среде стандартный каталог кеша npm недоступен для записи. Для установки используйте:

```bash
npm ci --cache /workspace/.cache/npm
```

Менять `HOME` не требуется; вне облачной среды обычный `npm ci` подходит.

Сайт: `http://localhost:3000`, панель: `http://localhost:3000/admin`. По умолчанию `PORT=3000`; при необходимости его можно задать в окружении процесса.

На первом открытии `/admin` создайте сотрудника: логин, имя и пароль длиной не менее 10 символов. Дальнейший вход выполняется по логину и паролю.

Начальные три точки посадки в Тбилиси — **тестовые demo-данные**, явно помеченные в интерфейсе. Перед использованием для реальных поездок сотрудник должен вручную внести названия и адреса точек в настройках. Точный адрес высадки в Дидубе также редактируется там и будет заполнен позднее.

## Сборка и production-запуск

Перед production-запуском задайте `DATABASE_URL` для PostgreSQL через защищённое окружение. На Vercel используется Neon; подробный порядок создания проектов и переменных приведён в [инструкции публикации](docs/deployment-vercel-neon.md).

```bash
npm run build
NODE_ENV=production npm run db:migrate
npm start
```

Миграция безопасна при повторном запуске; сборка не запускает её автоматически. API также инициализирует схему при старте под блокировкой PostgreSQL. Production-сервер размещается за HTTPS-прокси: защищённые cookies панели и подключение Android требуют HTTPS. Публикация облачной среды разработки сама по себе не размещает сайт в интернете.

Перед созданием первого сотрудника задайте `ADMIN_SETUP_TOKEN` через окружение сервера: сгенерируйте его локально из не менее 32 случайных байт. Первичная настройка сотрудника на `/admin` требует этот токен. После создания сотрудника уберите переменную из production-окружения и перезапустите процесс либо выполните новое развёртывание Vercel. Это внутренний секрет запуска: не записывайте его значение в репозиторий, README, клиентский код или чат. Пароли сотрудников также не входят в конфигурационные файлы.

## Данные

Локально без `DATABASE_URL` база сохраняется в `.data/greentaxi.sqlite`; путь меняется через `DB_PATH`. Каталог `.data` исключён из Git. В production `DATABASE_URL` обязателен, данные хранятся в PostgreSQL. SQLite-файл нельзя использовать как постоянную базу Vercel. Миграции и первоначальные demo-настройки не перезаписывают существующие заказы или настройки оператора.

## Печать заказов

В разделе заказов нажмите зелёную кнопку с принтером «ბეჭდვა». Выберите дату, весь день или отдельное время и одно либо оба направления. Расширенный предпросмотр содержит все подтверждённые активные заказы выбранного периода, независимо от поиска и страницы основной таблицы, с полным адресом посадки и итогом мест. Пять колонок идут в порядке «მისამართი», «ადგილები», «ტელეფონის ნომერი», «საათი», «ნომერი»: адрес посадки, места, телефон, час и номер строки. Направление указано в шапке отчёта. «ბეჭდვა / PDF» обновляет список и открывает системную печать браузера: вертикальный A4, адреса шрифтом 18 пунктов, телефоны и цифры — 20 пунктов. Длинные адреса переносятся, заголовки таблицы повторяются на следующих листах. Для PDF выберите сохранение в файл в диалоге браузера.

## Форма оператора

Ручной заказ заполняется без имени: локация, телефон, направление, места, день и час. Количество мест выбирается кнопками 1–8, день — «Сегодня / Завтра», все доступные часы видны сразу. Для сегодня скрыты уже наступившие часы по времени Грузии; открытая форма обновляет доступность. Телефонные обращения оформляются прямо в строках очереди, с календарём для других будущих дат и каруселью часов. Сервер проверяет действующее расписание и будущее время. Существующие заказы и история сохраняются; восстановление прежнего действующего слота не требует переноса.

## Очередь водителей

В «პარამეტრები» рядом с редактором часов показаны 43 водителя и вместимость их машин. Очередь действует для Гори → Тбилиси и идёт снизу вверх по постоянному списку: 19 октября 2026 первым идёт სუხიტა, 20 октября — გურამი, 21 октября — ერასტი. Каждый календарный день начало сдвигается к предыдущему водителю; после начала списка очередь продолжается с его конца. После 43 дней круг повторяется. ID водителей и их вместимость сохраняются. Отказ действует только на выбранную дату и не меняет начало следующих дней.

Назначения на часы больше не создаются автоматически. В настройках отображаются только дневная очередь, вместимость машин и отметки участия. Смена расписания, отказ или возврат водителя не назначают других водителей на рейсы. Уже сделанные вручную назначения сохраняются отдельно от очереди.

В «ჯავშნები» администратор выбирает дату и час, затем нажимает «მძღოლის მიბმა». Открывается окно с крупными кнопками активных водителей, в том же порядке, что в настройках на эту дату. На кнопке показаны номер очереди, имя и вместимость; неактивные на этот день водители не отображаются. Назначение свободного водителя выполняется одним нажатием. Если водитель уже стоит на другом часу, перенос нужно подтвердить отдельно. Один водитель может иметь одно явное назначение на день; на одном рейсе допускается несколько машин.

У назначенных машин показаны занятые и свободные места. Учитываются все подтверждённые неудалённые заказы рейса, независимо от поиска и страницы таблицы. Если машина ещё не назначена или мест недостаточно, недостающие места видны в блоке «მძღოლის გარეშე»; бронирования не блокируются по вместимости. Заказы целой машины резервируют именно выбранный автомобиль и защищают его от случайного снятия или переноса.

«შეცვლა / მოხსნა» открывает действия над уже назначенными машинами. Дополнительная временная машина остаётся второстепенным вариантом. Интерфейс выбора рассчитан на пожилых операторов: контрастные крупные подписи, большие кнопки, управление клавиатурой, закрытие Escape и возврат фокуса. Смена даты/часа и запоздалые ответы не переносят выбор на другой рейс. Данные обновляются автоматически; устаревшее сохранение отклоняется и требует повторного выбора после обновления.

Миграция `013_manual_driver_assignments` сохраняет действующие и исторические заказы целой машины, закрепляя их прежние машины явными назначениями. Явные назначения и отметки участия не стираются; противоречивые данные о двух рейсах одной машины останавливают миграцию атомарно. Внешние данные, пользователи и настройки не сбрасываются.

## Пассажирская главная

Страница оформлена по предоставленному макету: светлая форма-билет и зелёная информационная колонка. Бронирование проходит в три шага — поездка, адрес, контакты. Данные сохраняются при возврате назад; заявка поступает оператору после последнего шага. Счётчик пассажиров ограничен 1–4 местами, сетка времени показывает все действующие слоты из настроек. На мобильном форма идёт перед пояснениями, а ссылки навигации раскрываются кнопкой. Подпись об оплате на месте информационная: онлайн-платежей и расчёта стоимости нет.

## Повторные пассажиры

Во входящей карточке исходный номер SIM-звонка показан отдельно, под ним — редактируемый номер заказа. Оба сохраняются: номер заказа остаётся идентификатором пассажира. Следующий звонок с известного номера получает контакт из последнего созданного подтверждённого заказа, даже если тот впоследствии отменён. Отмена или перенос старой поездки не меняет этот выбор. Общий семейный номер не объединяет профили разных пассажиров.

Под адресом оператор отмечает «ბარგი», «ძაღლი» и предпочтение места «წინ / უკან / შუაში». Выбор можно снять; отметки относятся к конкретному заказу и не увеличивают количество мест. Они сохраняются при редактировании, удалении и восстановлении и видны в списке, истории пассажира и компактной печати.

В карточке входящего звонка показаны неудалённые заказы на сегодня и будущие дни, включая ожидающие и сегодняшние прошедшие часы, в обоих направлениях. Поиск учитывает точный номер звонящего, сохранённый номер звонка в заказе и текущий номер заказа, введённый оператором. Отмена после подтверждения переносит выбранный заказ в историю, освобождает его пассажирские места и обновляет другие карточки этого номера; входящий звонок и черновик новой поездки сохраняются. Кнопки оператора увеличены и получают контрастное выделение выбранного действия.

В разделе «მგზავრები» вместо имени показан последний адрес посадки. Поиск работает по адресу и телефону; список разделён на страницы. Адрес и кнопка истории открывают страницу пассажира `/admin/passengers/<номер>` с сохранёнными адресами и прошлыми поездками. Фильтры позволяют отдельно посмотреть предстоящие, ожидающие и удалённые заказы. Прямая ссылка работает после входа сотрудника; возврат в список сохраняет поиск и страницу. Страница доступна только в админке.

Сотруднику доступны сохранённые адреса по нормализованному номеру телефона. В очереди звонков город определяет адрес посадки: последний адрес дома в Гори либо последняя действующая точка Тбилиси. Адреса посадки сохраняются независимо; высадка в Гори не заменяет сохранённый адрес посадки в Гори. Для обратной поездки оператор также проверяет адрес высадки в Гори. Имя в операторской форме не запрашивается. Имена прежних заказов и профилей сохраняются. Дату и количество мест для новой поездки выбирают заново.

Во входящем звонке время подставляется из прошлых подтверждённых неудалённых заказов этого номера, отдельно для каждого направления. Предпочтение отдаётся самому частому часу; при равной частоте — часу наиболее поздней поездки. Если он уже прошёл сегодня или отключён в расписании, проверяются следующие часы из истории. Без подходящего времени выбор остаётся пустым. Смена дня позволяет использовать привычный час завтра; дата сама не переносится. Ручной выбор оператора не заменяется обновлением истории, а подтверждение заказа остаётся отдельным действием.

У пассажира может быть несколько адресов. Над полем адреса Гори сотрудник выбирает сохранённый вариант или «ახალი მისამართი / ხელით შეყვანა» и вводит новый. Новый адрес добавляется после подтверждения заказа; прежние варианты сохраняются. Выбор и ручной ввод сохраняются при обновлении очереди звонков. В Тбилиси используются настроенные остановки, ранее выбранные помечены как сохранённые. Страница пассажира показывает все сохранённые адреса по городам.

Грузинские номера хранятся как девять цифр и показываются в формате `568 69 48 79`, без `+995`. Номера с международным префиксом принимаются при вводе; существующие заказы и профили переводятся к единому ключу при запуске API. Международные номера других стран сохраняют свой код.

## Перенос исторических заказов

Для проверенного исторического списка предусмотрен приватный CLI: `npx tsx scripts/import-historical-bookings.ts --input /защищённый/путь/import.json`. По умолчанию он только проверяет план; `--apply` выполняет одну транзакцию. Также поддерживается `--input-env HISTORICAL_IMPORT_PAYLOAD` для защищённого серверного задания. Секрет подключения берётся из окружения; исходный список клиентов и значения переменных не записывают в Git или логи. `--report /защищённый/путь/report.json` сохраняет отчёт с ID заказов и номерами строк с правами `0600`.

JSON содержит `batchKey`, SHA256 исходного файла в `sourceHash`, `date`, направление `gori-tbilisi` и массив `records` с `sourceLine`, нормализованным телефоном, `address`, `seats`, `time` и флагом `deleted`. Проверяются прошлый день, заполненность данных и совпадения в базе. Неполные записи и неоднозначные совпадения требуют уточнения. Повторный запуск того же пакета сохраняет существующие ID и последующие изменения оператора. Исторические поездки сразу связаны с пассажирами и добавляют адреса, сохраняя более новые значения по умолчанию. Расписание сохраняет время исторической записи; постоянные часы не меняются.

Профиль обновляется после действий сотрудника с заказом. Публичные заявки сами не меняют сохранённые данные пассажира; публичная форма и API не раскрывают профиль по номеру телефона. До появления SMS-проверки автоподстановка работает только в защищённой панели.

## Звонки с Android

Дополнительный источник входящих — новые принятые SIM-звонки на Redmi с Android 15. Пропущенные, отклонённые и исходящие звонки не создают обращения; старый журнал не импортируется.

Сотрудник подключает устройство в настройках панели и передаёт выданный токен приложению на телефоне. Значение токена показывается при создании устройства; не сохраняйте его в репозитории или примерах конфигурации. Доступ устройства можно отключить там же.

Обычный входящий SIM-звонок создаёт телефонное обращение сразу после ответа, без параметров поездки. В строке оператор выбирает город отправления (Гори или Тбилиси), уточняет подставленный адрес посадки и телефон, выбирает 1–8 мест, «Сегодня / Завтра» либо другую будущую дату через календарь и проверяет час из карусели. Зелёные линии отделяют обращения. Время, статус звонка и устройство показаны компактно внутри расширенного блока «ჯავშანი», оставляя больше места карусели. Очередь разбита на страницы; автообновление не сбрасывает заполненные поля. Подтверждение сразу создаёт заказ, отказ сохраняет обращение в истории. После завершения звонка обновляется та же карточка; подтверждённый заказ сохраняется. Повторная доставка события не дублирует обращение. Подробнее: [Android-интеграция](docs/android-integration.md).

Владелец подтвердил получение завершённых SIM-звонков на Redmi Android 15, в том числе при заблокированном экране после настройки HyperOS. API и browser-проверки используют синтетические события. Раннюю отправку новой версии APK нужно отдельно проверить на том же телефоне; ожидающие и неоднозначные звонки могут появиться после завершения.

## Проверки

```bash
npm test
npm run test:e2e
```

Для e2e нужен Chromium, установленный для Playwright. Если браузер ещё не установлен:

```bash
npx playwright install chromium
```

`npm run build` также проверяет TypeScript. Сценарии приёмки перечислены в ТЗ; описание сценариев не является отчётом об успешном прохождении тестов.

Без PostgreSQL-переменных browser-тесты запускают отдельный сервер на порту 3100 и создают новую SQLite-базу в уникальном каталоге `/tmp` для каждого запуска. Рабочая `.data/greentaxi.sqlite` для них не используется.

Для PostgreSQL API-тестов задайте `TEST_DATABASE_URL` тестовой базы: проверки создают и удаляют изолированные схемы. Для PostgreSQL browser-тестов задайте `E2E_DATABASE_URL` **только одноразовой тестовой базы** — этот запуск не изолирует данные отдельной схемой. Команды остаются `npm test` и `npm run test:e2e`.

## Кабинет водителя

Страница `/driver` содержит вход и одностраничный кабинет водителя. Сверху водитель выбирает «დღეს / ხვალ» и отмечает «ვმუშაობ» либо «არ ვმუშაობ»; ниже отдельно выбирает день просмотра заказов. Даты определяются по времени Грузии. Отметка участия сразу видна в административной очереди, но не назначает часы автоматически. Если целая машина уже забронирована, отказ от рабочего дня требует обращения к администратору: существующая бронь сохраняется.

Персональный список пока содержит подтверждённые неудалённые заказы «მთლიანი მანქანა» с явным ключом машины вошедшего водителя. Обычные заказы связаны только с часом, поэтому не включаются в персональную выдачу без согласованного правила распределения между несколькими машинами. Нельзя выводить принадлежность заказа по порядку заполнения мест в сводке загрузки.

Учётные записи и сессии водителей отделены от сотрудников. Водителю доступны только его участие на сегодня/завтра и чтение разрешённых ему заказов. Административные API, изменение заказов и чужие учётные записи через этот вход недоступны. Пароли хранятся как хеши; миграция `014_driver_portal` создаёт пустые таблицы без стандартных логинов или паролей.

Логины добавляются вручную для существующего водителя, по одному. План команды ничего не записывает:

```sh
node --use-env-proxy --import tsx scripts/provision-driver-account.ts \
  --neon-existing --driver-id 1 --login rezo --expected-name რეზო
```

Для создания добавьте `--create` и передайте пароль через stdin или временную переменную `DRIVER_ACCOUNT_PASSWORD`. Не передавайте пароль аргументом команды, не сохраняйте его в Git или клиентском коде. Команда использует существующие проект и ветку Neon через `NEON_API_KEY`, проверяет имя водителя и создаёт запись вместе с записью журнала. Она не заменяет существующий аккаунт и не меняет пароли сотрудников. Схема должна быть обновлена обычным запуском API до выполнения команды. Без `--neon-existing` требуется существующий `DATABASE_URL`; режим `--local` требует явный `DB_PATH` и предназначен для локальной базы.

## ტიპები: გზავნილი და მთლიანი მანქანა

В операторской форме и в очереди телефонных обращений выбирается тип заказа: пассажир, «გზავნილი» или «მთლიანი მანქანა». Посылка сохраняется с нулём мест и не увеличивает занятость рейса. Для целой машины открывается окно с крупными кнопками всех водителей в порядке дневной очереди, включая отмеченных неработающими. Предварительно назначать водителя на час не требуется. В списке также доступны временные машины выбранного рейса Гори → Тбилиси. Для обратного направления назначений машин пока нет.

Выбор в окне меняет только черновик. При сохранении подтверждённого заказа назначение водителя и резерв всей реальной вместимости машины выполняются в одной транзакции. Перенос водителя с другого часа или включение неработающего водителя на выбранный день требует подтверждения; устаревший выбор и чужая эксклюзивная бронь блокируются. Отмена формы не меняет назначения и участие водителей. Места целой машины учитываются как занятые и не распределяются на другие машины. Удаление заказа освобождает резерв, восстановление проверяет конфликты. Изменение списка водителей не может незаметно отвязать активную эксклюзивную бронь. Название машины сохраняется в заказе и видно в списке и печати. Публичная пассажирская форма остаётся пассажирской.

Миграция `012_booking_types` сохраняет существующие заказы как пассажирские, вместе с их ID, связями звонков, журналом и параметрами. Она предусмотрена для SQLite и PostgreSQL; перед публикацией новой версии нужно применить её к существующей базе Neon обычным механизмом миграций, без создания нового проекта.
